# Thoth v0.4.0

## Highlights

- **Project filter.** A chip in the popover header picks one project or
  "All projects". Every number follows it: today, periods, activity, models,
  trends, the ranking and the heatmap. The menu is ordered by estimated cost,
  shows the top 10 directly and the rest under "More". The choice is kept
  between launches, and switching re-sums what is already in memory instead
  of re-reading files.
- **Know how fresh the numbers are.** The footer shows when the history was
  last read ("Updated 2 min ago"). Reading for the first time, no history,
  a folder that can't be read and a partial read each get their own notice,
  so a failed read never looks like a real zero.
- **Approximate prices are marked.** A model priced from the closest known
  version of its family shows "≈" and the reference rates. A model from an
  unknown family is counted in tokens and calls, marked "no known price",
  and left out of the cost total, with a note saying so.
- **How activity is inferred.** An info button in the activity section
  explains that categories come from the tools each turn used, in which
  order they are checked, and that they are not a measure of time or intent.

## Fixes

- Resumed or forked sessions copy responses into another transcript file.
  Each response is now counted once across all files (about 0.03% of the
  cost on a real history), and always in the file where it first appears,
  whatever the read order.
- Timestamps without fractional seconds were not read, so those responses
  were left out of the full scan.
- A response without `message.id` was counted once per line; it now falls
  back to the request id.
- Cache writes reported only as the `cache_creation` breakdown counted as 0.
- Responses without a timestamp are left out everywhere and counted as
  skipped lines, instead of counting as today in one view only.
- Sessions started in temporary folders (`/tmp`, `/var/folders`, scratchpads)
  and tool worktrees whose origin can't be told are grouped under
  "Temporary folders" instead of each showing as a project.

## Under the hood

- Log format compatibility tests: synthetic transcripts with malformed and
  truncated lines, missing and unknown fields, unknown record types and
  models, streaming repeats, subagents, compaction summaries, cache variants
  and growing files, each read whole, in chunks and incrementally.
- The README shows the popover (light and dark), rendered from synthetic
  data with `scripts/screenshots/capture.sh`.
- `docs/NOTARIZATION.md` records why the app is not notarised for now.

## Performance

Synthetic benchmark (600 files, 946 MB), release build: the full cold scan,
the today summary and the incremental scans stay within 1% of v0.3.0.
Switching the project filter takes about 0.4 ms.

## Compatibility

Unchanged: Universal app (Apple silicon and Intel), macOS 14 or later. The
app is still not notarised; the first launch needs the same steps as before.
